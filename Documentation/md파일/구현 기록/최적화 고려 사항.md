# 최적화 고려 사항

> 문서 방침: "최적화보다는 구현에 치중. 다만 구현 시 최적화의 문제가 될 부분은 미리 md 로 기록" — 현재 구현에서 규모가 커지면 문제가 될 지점입니다.
> 우선순위: **높음** = 4인 + 보스 상황에서도 프레임 드랍/GC 스파이크 가능, **중간** = 모바일 또는 NetCode 단계에서 문제, **낮음** = 규모가 커질 때.

## 전투 / GAS

| 우선 | 위치 | 문제 | 개선 방향 |
|---|---|---|---|
| 높음 | `SkillAbility.executeHit`, `BossPatternAbility.applyHit` | 타격 1회 · 대상 1명마다 `GameplayEffectSpec` 생성 → 시전자 속성 스냅샷 배열(44칸) 복사 + SetByCaller `Dictionary` 할당 | Spec 풀링, 스냅샷을 타격 단위로 공유 |
| 높음 | `SkillAbility.scheduleNext` | 타격마다 람다 캡처 + `WaitDelayTask` 할당 | 타격 타임라인을 한 태스크가 인덱스로 진행 |
| 중간 | `SkillDamageExecution.IndependentMultiplier` | 타격마다 시전자의 모든 활성 이펙트 · 모디파이어를 순회 | 독립 곱 배율을 이펙트 추가/제거 시점에 캐시 |
| 중간 | `CombatRegistry.FindHostiles/FindTeam` | 선형 탐색 (현재 5~6명이라 문제 없음) | 소환물/잡몹이 늘면 공간 분할(그리드) |
| 중간 | `EventBus<DamageAppliedEvent>` | 타격마다 발행 → HUD · 딜 미터 · 테스트 리스너 | 프레임 단위 배치 발행 |
| 낮음 | `EffectScaling` 캐시 | (정의, 배율) 쌍이 계속 쌓임 | 빌드 변경 시 정리 |
| 낮음 | `BuildCalculator` | 빌드 적용마다 GameplayEffectDef 새로 생성 (전투 밖이라 영향 작음) | 동일 결과면 재사용 |

## NetCode 단계에서 다시 볼 것

- GAS 는 오프라인 권한 기준. 서버 권한으로 옮길 때 Spec 생성/판정은 서버, 연출(GameplayCue)만 클라이언트로 분리해야 트래픽이 작다.
- `GameRandom` 은 단일 시드. 서버가 시드를 정하고 패턴 선택 결과만 전파하는 구조가 유리하다.
- 장판 추적(`TrackDuringTelegraph`)은 매 프레임 위치 동기화가 필요 → 고정 시점만 전송.
