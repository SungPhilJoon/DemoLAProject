## 1. 능력치 / 피해 공식

| 상태 | 항목 | 현재 처리 (`StatFormulaSettings`, `DamageCalculator`) | 결정 답변 |
|---|---|---|---|
| 🟡 | 전투 특성 환산 (치명/특화/신속) | 치명 → 치명타 적중률, 신속 → 공속/이속/쿨감 계수만. 값은 자리 표시 | 시즌2 기준 계수 확정 (확실하지 않은 공식은 원작을 따라할려고 하는 것이 아닌 로아인벤에서 확인한 어림한 공식 수치를 적용하면 됨.) |
| ⛔ | 특화 · 제압 · 인내 · 숙련 효과 | 특화는 아이덴티티 게이지 획득량에 임시 연결, 나머지 효과 없음 | 원작과 똑같이 구현하되 공식은 로아인벤에 있는 수치를 사용하여 어림잡아 계산할 수 있도록 만듦. |
| 🟡 | 공격력 공식 | `sqrt(주스탯 × 무기공격력 / 6) × (1 + 공격력%)` (커뮤니티 공식으로 알려진 형태, 미검증) | 이대로 적용 |
| ❓ | 피해 증가의 합/곱 그룹 | `DamageIncrease`(합) · `IndependentDamage`(이펙트마다 곱) · 보석(곱) · 방향(곱) 로 나눔 | 각인은 각인 효과마다 다르게 구현할 수 있도록 하면 됨. 효과의 구체적인 내용은 로아 인벤에서 내용을 확인. 각인 효과랑 똑같이 구현. 카드도 로아 시즌2랑 똑같이 구현. 세트와 버프도 마찬가지로 원작과 똑같이 구현한다. 내용은 로아 인벤이나 공식 사이트, 그리고 로아온 사이트에 직접 검색해서 확인한다. |
| 🟡 | 방어력 공식 | `Def / (Def + 6500)` 감소 · 방어 관통 지원 | 그대로 똑같이 진행. |
| ❓ | 백/헤드어택 | 스킬에 백어택/헤드어택 속성이 있을 때만 +5% (각도 120°/60°). 백어택 추가 치명타 적중률 미적용 | 로아랑 똑같이 구현한다. 추가 치명 보너스가 있는 것 같다는 여론이 많다면 적용하도록 한다. 각도는 에디터에서 수정할 수 있도록 만든다. |
| 🟡 | 마나 회복 · 이속/공속/쿨감 상한 | 초당 15 · 140% · 80% | 그대로 적용. |
| ⛔ | 아이덴티티 (직업 고유 시스템) | 공용 `IdentityGauge` 만 적중 시 충전. 사용처 없음 | 4직업 모두 각각 직업마다 로스트아크 시즌2랑 똑같이 구현한다. 아이덴티티를 모으는 과정과 사용, 그리고 사용 스킬등 모두 원작과 똑같이 구현한다. |

| ❓ | 페이즈 경계 줄 수 (출처마다 다름) | 46 / 30 / 16 (1관문), 131(방어 구슬, 가정) / 130 / 88 / 65 / 30 / 16 / 유령 40줄 (2관문) | 로스트아크 시즌2랑 똑같이 구현. |
| 🟡 | 어그로 | 받은 피해량 = 위협 수치 | 규칙 (도발, 감쇠, 무작위 전환) 그대로 적용. 다만 무작위 전환 시 여러 방식이 있다. 70%의 확률로 가까운 캐릭터를 타겟으로 잡고 30%의 확률은 랜덤한 캐릭터를 타겟으로 잡게 한다. 70%나 30%의 수치는 에디터에서 수치를 변경해서 적용할 수 있도록 변경. |
| ❓ | 인원 | 문서 최대 4인 — xlsx 는 8인 레이드 기준 기믹(구슬 8개 등) | 4인용으로 개수/시간 조정 |
| ⛔ | 에스더 스킬 | 없음 (xlsx 의 대체 공략 경로) | 에스더 무기나 스킬은 없음. |
| ⛔ | 배틀 아이템 | 시간 정지 물약 · 만능약/정화 · 파괴 폭탄 · 회복약 없음 | 배틀 아이템을 넣고 배틀 아이템 쿨다운/개수는 로스트아크 시즌2랑 똑같이 구현. |

### 7-2. 패턴별

여기 내용은 무조건 로스트아크 시즌2랑 똑같이 구현하면 됨. 결정의사는 로스트아크 시즌2를 기준으로 로아인벤이나 로아 발탄레이드의 유튜브 영상의 스크립트를 확인하여 결정.

## 9. UI · 저장 · 멀티플레이 · 에셋 관리

| 상태 | 항목 | 현재 처리 | 결정 답변 |
|---|---|---|---|
| 🟡 | UI 구현 방식 | uGUI 를 코드로 조립(프리팹 없음). 한글은 내장 LegacyRuntime 폰트(OS 글꼴 대체) | 일단은 그대로 구현하고 후에 UI에 관련된 구체적인 결정은 후에 차수에서 결정하도록 한다. |
| ⛔ | PlayFab | `ISaveService` 인터페이스만 (현재 `LocalJsonSaveService`) | 로그인 기능, 데이터 저장 기능, 인벤토리, 상점 등의 기능을 구현할 때 사용. |
| ❓ | "Delay 로비" | 의미 불명확 (대기실? 지연 시작? 레이턴시 보정?) | Relay 로비 구현을 뜻함. Netcode로 서로 다른 LAN의 유저와 같이 플레이 할 수 있도록 만들려고 하는데 이 기능들을 무료로 사용하고 싶음. 무료로 다른 LAN 에 있는 플레이어와 같이 플레이 할 수 있도록 구현했으면 좋겠어서 말함. |
| ⛔ | NetCode for GameObjects | 패키지 미설치. GAS 는 오프라인 권한 구조 | GAS에 서버 권한 규칙을 적용할 수 있도록 현재 데스크탑에 있는 프레임워크의 코드를 변경하도록 함. 그리고 후에 바뀐 프레임워크로 업데이트할 예정. AI는 플레이어가 결정하지 않은 직업은 AI로 플레이어가 선택한 직업은 플레이어가 플레이할 수 있도록 변경. 일단은 Framework 패키지의 GAS구조와 다른 구조를 Netcode와 연동할 수 있도록 수정. |
| 🟡 | Addressables | `GameDatabase` 1개만 주소 등록 (없으면 코드 기본값) | 카탈로그는 일단 Default로 설정. 그룹 구성은 에셋 의존성을 체크하는 툴을 제작하여 의존성 체크 확인 후 그룹을 자동으로 설정할 수 있도록 자동화 작업을 넣을 예정. 일단은 에셋 의존성 툴을 제작. |
| ❓ | 딜량 테스트 기준 | 테스트는 "피해가 난다 / 풀세팅이 맨몸보다 1.2배 이상" 만 확인 | 딜량은 런타임에서 지속적으로 확인할 수 있도록 런타임에서 확인할 수 있는 툴을 제작한다. 그리고 밸런스 툴을 구현하는데 이는 밸런스 툴 제작에 대한 모범적인 사례를 확인하여 수정. |
| ⛔ | Android 플랫폼 전환 | 빌드 타깃 전환은 하지 않음 (에디터에서 직접) | 빌드 타깃 전환은 후에 수정. |
| ❓ | 게임 정적 데이터 | 미구현 상태 | 게임 정적 데이터는 ActionRPGProject의 스크립터블 오브젝트를 사용한 방식처럼 구현. 이는 Framework에 적용하도록 수정. 게임 정적 데이터는 csv -> 스크립터블 오브젝트로 변환하고 이를 사용하는 방식으로 변경하는데 csv와 스크립터블 오브젝트를 Resources 파일에 넣지 않도록 한다. 되도록이면 Local Bundle을 사용한 Addressables를 사용하지 Resources에 리소스를 저장하는 방식은 사용하지 않는다. |
