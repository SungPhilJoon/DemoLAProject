# 패턴 대상 선택 (어그로 규칙) 사용법

보스 패턴(스킬)마다 **누구를 노리는지** 정한다.
예를 들어 돌진은 가장 먼 사람, 마무리 패턴은 체력이 가장 낮은 사람, 일반 공격은 지금 어그로 대상을 노리게 할 수 있다.

정하는 곳은 두 군데이고, 둘 다 같은 규칙(`PatternTargetSelector`)을 쓴다.

| 정하는 곳 | 언제 쓰나 |
|---|---|
| **StateTree 노드** (`SelectTargetTask` · `TargetRuleCondition`) — 권장 | AI 흐름 안에서 정할 때. "가장 먼 사람이 10m 이상이면 그 사람에게 돌진", "체력이 가장 낮은 사람을 어그로로 고정"처럼 **조건과 대상 선택을 함께** 다룰 때 |
| **패턴 에셋** (`BossPatternDefinition.TargetSelector`) | 언제 쓰든 **항상 같은 규칙**으로 노리는 패턴일 때. StateTree 가 따로 지정하지 않았을 때의 기본값이 된다 |

- 규칙: `Assets/_Project/Scripts/Runtime/Boss/PatternTargetSelectors.cs`
- StateTree 노드: `Assets/_Project/Scripts/Runtime/AI/BossTargetNodes.cs` — StateTree 에디터의 **DemoLA/Boss** 분류
- 패턴 에셋 툴: **GAS Tool** (DemoLA → Tools → GAS Tool) 의 Ability 탭 → 대상 섹션 — [GAS Tool (보스 패턴 · 카운터).md](GAS%20Tool%20(보스%20패턴%20·%20카운터).md)
- 테스트: `Assets/_Project/Tests/EditMode/PatternTargetingTests.cs` (`Tools/dev.sh test editor PatternTargeting`)

## 1. 대상이 정해지는 순서

패턴이 시작될 때 **첫 대상(패턴 대상)**을 한 번 정한다 (`PatternTargeting.Resolve`).

| 순서 | 조건 | 대상 |
|---|---|---|
| 1 | 보스가 도발에 걸려 있음 | 도발한 플레이어. 어떤 규칙보다도 우선한다 |
| 2 | StateTree `SelectTargetTask`(**NextPattern**)가 대상을 지정했거나, 시나리오 · 디버그 명령이 대상을 넘김 | 지정된 대상 (살아 있을 때만, 패턴 1회만) |
| 3 | 패턴 에셋에 **대상 규칙**이 지정됨 | 규칙이 고른 플레이어. 못 고르면 다음 순서로 넘어간다 |
| 4 | 그 밖의 경우 | 보스의 현재 어그로 대상. `BossDefinition.Aggro` 규칙으로 정해지며, `SelectTargetTask`(**Aggro**)로 바꿀 수 있다 |

> 아무것도 지정하지 않으면 기존 동작(현재 어그로 대상을 노림)과 같다. 그래서 필요한 곳에만 지정하면 된다.

### 대상이 쓰이는 단계

패턴은 여러 단계(`Steps`)로 이루어진다. 정한 대상은 **`Targeting` 이 아래 둘 중 하나인 단계**에서만 쓰인다.

| 단계 Targeting | 패턴 대상을 쓰는가 |
|---|---|
| `AggroTarget` | ✅ 패턴 대상의 발밑에 장판이 생긴다 |
| `BossTowardAggro` | ✅ 보스가 패턴 대상 쪽을 보고 장판을 편다 |
| `RandomPlayer` · `EachPlayer` | ❌ 단계가 대상을 스스로 고른다 |
| `BossForward` · `ArenaCenter` | ❌ 대상과 상관없다 (보스가 처음에 바라보는 방향만 바뀐다) |

## 2. StateTree 노드로 정하기 (권장)

보스 StateTree 에셋(`Data/Generated/StateTree/ST_Gate*.asset`)을 StateTree 에디터로 연다.
상태의 **Tasks** 또는 **Enter Conditions** 에서 `+` 를 누르고 **DemoLA/Boss** 분류를 고르면 두 노드가 있다.
노드 안의 **Selector** 칸에서 규칙을 고른다. 목록은 5장 표와 같다.

### 2-1. `SelectTargetTask` — 대상 지정 (태스크)

| 필드 | 의미 |
|---|---|
| `Selector` | 대상 규칙 (기본값 `Farthest`) |
| `ApplyTo` | **NextPattern** = 다음에 쓰는 패턴 1회의 대상만 바꾼다. 블랙보드 `PatternTarget` 에 들어가고, 패턴을 쓰면 지워진다 |
|  | **Aggro** = 보스의 어그로 대상 자체를 바꾼다. 보스가 쫓아가는 대상과 이후 모든 패턴의 기본 대상이 바뀐다 |
| `HoldSeconds` | Aggro 일 때, 이 시간 동안 어그로를 자동으로 다시 고르지 않는다. 0 = 보스의 `RetargetInterval` |
| `FailIfNone` | 고를 대상이 없으면 Failed. 끄면 아무것도 바꾸지 않고 Succeeded |
| `Announce` | 고른 대상의 이름을 레이드 메시지로 띄운다 (기믹 안내 · 디버그) |
| `CompleteImmediately` | 기본값은 **꺼짐**이다. 꺼 두면 Running 으로 남아, 같은 상태의 다른 태스크(패턴 태스크)가 끝날 때까지 기다린다. 이 태스크 하나만 있는 상태에서만 켠다 |

같은 상태 안에서 **`UsePatternTask` / `UseRandomPatternTask` 보다 앞에** 둔다. 상태에 들어갈 때 태스크가 위에서부터 차례로 진입하므로, 이렇게 해야 대상이 먼저 정해진다.
StateTree 는 상태 안의 태스크가 **하나라도** 끝나면 그 상태를 끝낸다. `CompleteImmediately` 를 켜면 대상을 고르자마자 상태가 끝나 패턴이 끝나기를 기다리지 않으므로, 패턴 태스크와 함께 둘 때는 꺼 둔다.
NextPattern 으로 대상을 지정하면 `UseRandomPatternTask` 의 사거리(`MinRange`~`MaxRange`) 검사도 지정한 대상까지의 거리로 한다.

### 2-2. `TargetRuleCondition` — 대상 검사 (조건)

| 필드 | 의미 |
|---|---|
| `Selector` | 대상 규칙 |
| `CompareDistance` · `Op` · `Distance` | 고른 대상까지의 거리 비교 (보스 중심 ~ 대상 몸 가장자리, 평면 거리 m). 끄면 "고를 대상이 있는가"만 본다 |
| `Invert` · `Operand` | 다른 조건과 같다 (부정 · And/Or) |

### 2-3. 2관문(`ST_Gate2`)에 적용된 상태

코드 `DefaultTrees.addGate2TargetingStates` 에 있으므로 `setup overwrite` 를 해도 유지된다. 기믹 상태들 뒤, `패턴 공격` 앞에 있다.

| 상태 | 진입 조건 | 태스크 |
|---|---|---|
| 원거리 견제 돌진 (G2-11 → 가장 먼 대상) | G2-11 준비됨 · 가장 먼 사람이 8m 이상 · 확률 50% | `SelectTargetTask(Farthest)` → `UsePatternTask(G2-11)` |
| 레이저 견제 (G2-16 → 위협 2위) | G2-16 준비됨 · 위협 2위가 있음 · 확률 40% | `SelectTargetTask(HighestThreat 2위)` → `UsePatternTask(G2-16)` |
| 약자 사냥 (G2-P3 · 체력 비율 최저 어그로 8초) | 페이즈 G2-P3 · 확률 25% | `SelectTargetTask(LowestHealth, Aggro, 8초, 알림)` → `UseRandomPatternTask(G2-공통)` |

확률 조건은 패턴을 고를 때마다 다시 굴린다. 조건에 맞지 않으면 기존 `패턴 공격`(가중치 랜덤)으로 넘어간다.
플레이로 확인한 결과: 플레이어가 멀리 있을 때 원거리 견제 돌진 → G2-11, 레이저 견제 → G2-16 이 실제로 쓰였다.

### 2-4. 예시

**가장 먼 사람이 10m 이상 떨어져 있으면 그 사람에게 돌진**
```
상태 "원거리 견제 돌진"
  Enter Conditions: TargetRuleCondition { Selector = Farthest, Op = >=, Distance = 10 }
                    PatternReadyCondition { PatternId = G2-11 }
  Tasks:            SelectTargetTask { Selector = Farthest, ApplyTo = NextPattern }
                    UsePatternTask   { PatternId = G2-11 }
```

**체력 줄이 50 이하로 내려가면 체력 비율이 가장 낮은 사람을 8초 동안 쫓기**
```
상태 "약자 사냥"
  Enter Conditions: HpLineCondition { <= 50 }
  Tasks:            SelectTargetTask { Selector = LowestHealth, ApplyTo = Aggro, HoldSeconds = 8 }
                    UseRandomPatternTask { CommonPhaseId = G2-공통 }
```

**위협 수치 2위에게 다음 패턴 쓰기 (탱커가 아닌 사람 견제)**
```
Tasks: SelectTargetTask { Selector = HighestThreat(Rank 2) }
       UseRandomPatternTask
```

> `FrontCone` 은 각도 안에 아무도 없으면 가장 가까운 사람을 대신 고른다. "정면에 누가 있는가"만 검사하려면 `CompareDistance` 를 켜고 거리를 짧게 잡는다.

> `Random` 규칙을 조건과 태스크에 각각 넣으면 따로따로 뽑는다. 그래서 조건에서 본 사람과 태스크가 고른 사람이 다를 수 있다.

## 3. 패턴 에셋에 기본 규칙 정하기 — GAS Tool

StateTree 가 대상을 지정하지 않았을 때 쓰는 패턴별 기본값이다.

1. **DemoLA → Tools → GAS Tool** → **Ability** 탭에서 패턴을 고른다.
   StateTree Editor 의 패턴 ID 칸 옆 **GAS** 버튼이나, 패턴 에셋 ⋮ 메뉴의 **GAS Tool 에서 열기** 로도 열 수 있다.
2. **대상 (누구를 노리는가)** 섹션의 **기본 대상 규칙** 드롭다운에서 규칙을 고른다. 옵션이 있는 규칙은 ▶ 를 펼쳐 값을 바꾼다.
3. 값은 패턴 에셋에 바로 저장되고 **Ctrl+Z** 로 되돌릴 수 있다.

화면 구성 전체는 [GAS Tool (보스 패턴 · 카운터).md](GAS%20Tool%20(보스%20패턴%20·%20카운터).md) 를 본다.

## 5. 제공하는 규칙

| 드롭다운 이름 | 클래스 | 고르는 대상 | 옵션 |
|---|---|---|---|
| CurrentAggro | `CurrentAggroSelector` | 현재 어그로 대상 | — |
| Nearest | `NearestSelector` | 보스와 가장 가까운 플레이어 | — |
| Farthest | `FarthestSelector` | 보스와 가장 먼 플레이어 (돌진 · 원거리 견제) | — |
| HighestThreat | `HighestThreatSelector` | 위협 수치 N위 (누적 피해, 초당 `ThreatDecayPerSecond` 비율로 줄어든다) | `Rank`: 1 = 1위. 인원보다 크면 꼴찌 |
| LowestHealth | `LowestHealthSelector` | 남은 체력 비율이 가장 낮은 플레이어 (마무리) | — |
| Random | `RandomSelector` | 무작위 1명 | `ExcludeAggro`: 현재 어그로 대상을 뺀다 (다른 사람이 없으면 어그로 대상) |
| FrontCone | `FrontConeSelector` | 보스 정면 기준 각도 안에서 가장 가까운 플레이어. 각도 안에 아무도 없으면 가장 가까운 플레이어 | `Angle` 10~360° |

공통:
- 죽었거나 대상으로 지정할 수 없는(`IsTargetable == false`) 플레이어는 후보에서 빠진다.
- 점수가 같으면 플레이어 목록에서 앞쪽에 있는 사람을 고른다.
- 무작위는 `GameRandom` 을 쓴다. 그래서 시드를 고정한 테스트 · 시뮬레이션에서는 결과가 매번 같다.

## 6. 새 규칙 추가하기

`PatternTargetSelector` 를 상속하고 `[Serializable]` 을 붙인다. 기본 생성자가 있어야 하며, 파일 위치는 어디든 된다.
다시 컴파일하면 StateTree 노드 · 인스펙터 · 툴의 드롭다운에 **자동으로** 나온다. 드롭다운 이름에서는 클래스 이름 끝의 `Selector` 가 빠진다.

```csharp
using System;
using System.Collections.Generic;
using DemoLA.Combat;
using UnityEngine;

namespace DemoLA.Boss
{
    /// <summary>보스 뒤쪽(각도 안)에 있는 플레이어 중 가장 가까운 사람. 없으면 null → 다음 순서로.</summary>
    [Serializable]
    public class BehindSelector : PatternTargetSelector
    {
        [Range(30.0f, 180.0f)] public float Angle = 120.0f;

        public override CombatActor Select(BossActor InBoss, IReadOnlyList<CombatActor> InCandidates)
        {
            var back = -InBoss.Forward;
            back.y = 0.0f;
            return Best(InCandidates, c =>
            {
                var to = c.Position - InBoss.Position;
                to.y = 0.0f;
                return Vector3.Angle(back, to) <= Angle * 0.5f ? -to.magnitude : float.NegativeInfinity;
            });
        }

        public override string Describe()
        {
            return $"뒤쪽 {Angle:0}° 안 가장 가까운 대상";
        }
    }
}
```

| 도우미 (protected) | 용도 |
|---|---|
| `IsValid(actor)` | 살아 있고 대상으로 지정할 수 있는가 |
| `Best(candidates, score)` | 점수가 가장 높은 유효한 후보. 점수가 `-∞` 인 후보는 고르지 않는다 |
| `FlatDistance(boss, actor)` | 높이를 뺀 평면 거리 |

규칙에서 쓸 수 있는 보스 정보: `InBoss.AggroTarget` · `InBoss.Threat` · `InBoss.Position` · `InBoss.Forward` · `InBoss.TauntTarget`.

> 패턴 에셋의 규칙 객체는 **같은 패턴을 쓰는 모든 보스 인스턴스가 함께 쓴다.** 그래서 필드에 실행 중 상태를 저장하지 않는다. 필요하면 `RandomSelector` 처럼 `[NonSerialized]` 버퍼만 둔다.
> StateTree 노드 안의 규칙은 트리 인스턴스마다 복제되므로 이 문제가 없다.

## 8. 자주 묻는 것

- **StateTree 와 패턴 에셋에 둘 다 지정하면?** → StateTree 가 지정한 대상이 이긴다. 패턴 에셋 규칙은 StateTree 가 아무것도 지정하지 않았을 때의 기본값이다.
- **보스가 평소에 쫓아가는 대상(어그로)도 바뀌는가?** → 패턴 에셋 규칙과 `SelectTargetTask`(NextPattern)는 패턴 1회의 대상만 정하므로 어그로는 바뀌지 않는다. 어그로 자체를 바꾸려면 `SelectTargetTask` 의 `ApplyTo = Aggro` 를 쓴다.
- **도발 중에도 규칙대로 움직이게 하고 싶다** → 지금은 도발이 항상 우선한다 (탱커 역할을 지키기 위해서다). 바꾸려면 `PatternTargeting.Resolve` 의 1번 순서와 `BossActor.AggroTarget` 을 고친다.
- **단계마다 다른 대상을 노리게 하고 싶다** → 대상은 패턴 단위로 정해진다. 그 단계의 `Targeting` 을 `RandomPlayer` · `EachPlayer` 로 두거나, 패턴을 나눠 `LinkedPatternId` 로 잇는다.
